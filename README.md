# 钉钉 WiFi 打卡（ESP32-C3 版）

用 ESP32-C3 广播一个 **SSID 和 BSSID 都跟目标热点一模一样** 的 AP，手机连上它就能通过钉钉的 WiFi 打卡校验。

> 基于 [Starryccc/DingDing_WiFi](https://github.com/Starryccc/DingDing_WiFi) 修改，加了「配置模式」和「扫描附近 WiFi」两个功能。
> 仅供学习 ESP32 的 AP 模式与 MAC 设置，请遵守你所在公司的考勤制度。

---

## 原理

钉钉 WiFi 打卡校验的是「手机当前所连网络的 **SSID + BSSID**」这一对值：

| 值 | 是什么 |
|---|---|
| **SSID** | WiFi 名字，手机 WiFi 列表里显示的那个 |
| **BSSID** | 这个热点的 MAC 地址 —— **AP 自己的 MAC**，不是手机的 |

固件在建立热点**之前**调用 `esp_wifi_set_mac(WIFI_IF_AP, ...)`，把板子 AP 接口的 MAC 改成目标值，
再 `WiFi.softAP()` 广播出去。于是手机连上的这个热点，在钉钉眼里就是原来的那一个。

> ⚠️ **最容易搞错的一点**：配置页里 MAC 那一栏要填的是「**目标热点的 BSSID**」，
> **不是手机的 MAC**，也不是板子自己的芯片 MAC（那个值会被直接覆盖掉）。
> 填错的话热点名字对了、打卡照样不通过，而且**从表面完全看不出异常**。

## 快速开始

需要 [PlatformIO](https://platformio.org/)（VSCode 插件或 CLI 都行）。

```bash
pio run -t upload      # 编译 + 烧固件（src/）
pio run -t uploadfs    # 烧网页文件（data/ → LittleFS）
pio run -t monitor     # 串口日志，Ctrl+C 退出
```

**改了哪里就烧哪个：**

```
改了 src/            →  pio run -t upload
改了 data/           →  pio run -t uploadfs
两边都改了           →  两个都跑
```

> ⚠️ `monitor` 开着的时候 `upload` 会失败（串口被占用，报 `could not open port`），**烧录前先关掉监视器**。
> 换到带 CH340/CP2102 串口桥的板子时，`upload_speed = 3000000` 可能烧不进去，降到 `921600` 或 `460800`。

## 怎么用

### 1. 填配置

1. 板子上电，广播默认热点 **`WIFI MANAGER`**（无密码）
2. 手机连上它 —— 一般会**自动弹出**配置页（固件里跑了 DNS 劫持 + `onNotFound` 跳转）；没弹就手动打开 `http://192.168.4.1`
3. 填三个字段：

   | 字段 | 填什么 | 约束 |
   |---|---|---|
   | **SSID** | 目标 WiFi 的名字 | 必填，≤ 32 字节 |
   | **Password** | 目标 WiFi 的密码 | 可为空（开放网络）；非空时 ≥ 8 位 |
   | **MAC** | 目标热点的 **BSSID** | 必填，严格 `aa:bb:cc:dd:ee:ff` 格式（17 字符） |

4. 点 **👌**

配置存在 NVS 分区里，**断电不丢**，以后每次上电自动重建热点。

### 2. 不知道 BSSID 是多少？

**用配置页自带的「📡 扫描附近 WiFi」** —— 配置页下半部分那张卡片：

1. 点「开始扫描」，等 2–6 秒（扫描期间热点会短暂卡顿，手机可能提示"无互联网"，属正常）
2. 列出板子能搜到的热点，按信号从强到弱排，每行是 `名字 · MAC(BSSID) · 信道 · 信号 · 加密`
3. 点某一行的「填入」，名字和 MAC 自动填进表单

不需要装 App、不需要管理员权限。隐藏网络会显示成「（隐藏网络）」，按钮变成「只填MAC」。

**板子扫不到怎么办？** ESP32-C3 是 2.4GHz 单频，扫不到 5G 网络。这种情况用别的途径拿 BSSID：

- **钉钉考勤后台** → 考勤组 → WiFi 打卡设置，里面就登记着 SSID + MAC。最准，零猜测
- **Android** 装 *WiFiAnalyzer* 之类的 App，2.4G / 5G 的 BSSID 都能看到
- **Windows**：`tools\get-bssid.ps1`（自动提权，需开启系统「位置服务」）
- **路由器后台**：无线设置里的 `BSSID` / `2.4G MAC`

> ⚠️ iPhone 设置里那个「Wi-Fi 地址」是**手机的** MAC，不是 BSSID，别抄错。

### 3. 按键

| 操作 | 功能 | 已保存的配置 |
|---|---|---|
| **1.5 秒内连按 3 次** BOOT | 进入配置模式：临时改回广播 `WIFI MANAGER` + 恢复强制门户 | ✅ 保留 |
| **长按 > 1 秒** BOOT | 清空配置并重启，回到默认热点 | ❌ 丢失 |
| 按一下 RST | 硬件复位 | ✅ 保留 |

按键都是**松手那一刻**才判定：0.8 秒以内算短按，超过 1 秒算长按。

**换 WiFi 推荐用三击**，因为「连旧热点直接改」有个会卡死的场景：公司连密码一起换了、手机忘了那个网络、
或者手机嫌"无互联网"拒绝连接，你就连不上旧热点、也打不开配置页，只能长按清空重配。

> ⚠️ **上电/复位时不要按着 BOOT**。GPIO9 是 ESP32-C3 的 BOOT 选通脚，被按住会让芯片进 **ROM 下载模式**，
> 固件根本不跑（现象：热点消失、串口没日志，看起来像板子坏了）。拔掉 USB、松手、重新插上即可恢复，没有后遗症。
>
> 配置模式最多保持 **5 分钟**，超时自动重启回到已保存的配置，不会一直卡在 `WIFI MANAGER` 上。

## 已知限制

- **只有 2.4GHz。** ESP32-C3 单频，扫不到、也连不上 5G 网络。填 5G 的 BSSID 是可以的 —— 伪装 MAC 跟频段无关。
- **连上后没有外网。** 纯 AP，没有 STA 上行。打卡时让手机连着它即可（或者开移动数据）。
- **发射功率被调低了。** 建自定义热点时调了 `esp_wifi_set_max_tx_power(34)`（≈ 8.5 dBm），这是原作者为**降低发热**做的。
  信号弱、连不上就把这个值调大（单位 0.25 dBm，`68` = 17 dBm）。
- **LED 不一定亮。** GPIO8 在不同板子上接法不同（官方 XIAO 根本没用户 LED，DevKitM-1 的 GPIO8 是 WS2812）。
  判断成功以「手机能不能搜到你填的 SSID」为准。
- **提交成功后网页不给提示。** 固件在重建热点前没有回响应，加上旧热点被断开，手机 `fetch` 必然失败。
  前端已经做了 `catch`，会提示「已提交。热点正在重建…」。
- **SSID 长度校验前端和固件不一致。** 网页表单限 32，但固件只检查 > 63 才报错。
  正常用表单不受影响；用 `curl`/Postman 直接 POST 33–63 字符的 SSID 会在 `WiFi.softAP()` 那一步失败，
  而且报的是 `创建热点失败，请检查MAC地址是否正确`，会误导你去查 MAC。
- **配置回退。** 开机时如果保存的 SSID 为空或 MAC 长度不等于 17，会自动回到 `WIFI MANAGER`，不会变砖。

## 与上游的差异

| 功能 | 说明 |
|---|---|
| 三击 BOOT 进配置模式 | 换 WiFi 不用清空重配，且 5 分钟超时自动回落 |
| 配置页「扫描附近 WiFi」 | 现场直接扫出 BSSID 并填入，解决 Android 10+ / iPhone 看不到 BSSID 的问题 |
| 提交失败兜底 | `createAP()` 失败时若设备已失联，自动重播默认热点 |
| `tools/` 脚本 | 抓开机日志、查询 BSSID |

实现细节和踩过的坑见 [使用说明.md](使用说明.md)。
